# 项目方案

## 要解决的问题

用户已有「小说自动生成器」的同楼层批量写卡模式。名单按行给出完整角色名，固定提示词中的 `[[角色名]]` 随名单替换。希望为每一轮角色提供对应图片，让同一聊天模型直接读取图片。

## 中转站怎么分工

收集时，把任务名单写入该作品文件夹的 `00-清单.md`。这份文件既是任务目标，也是目录：在 GitHub 打开文件夹时排在最前，角色名可点击打开图片，勾选状态一眼能看出进度。图片与名单对应后勾选；找不到或不合格则保持未勾选，必要时注明失败原因。

`images/` 下一部作品一个文件夹，例如 `原神`、`星穹铁道`、`崩坏3`。每个文件夹都是自包含的，含清单、由清单生成的 `catalog.json` 和图片。下载时只打包这一文件夹，不要把整个仓库打成一个包。

公开仓库中的角色图片版权归原权利人所有，仅供个人整理和导入使用。不要把密钥或私人数据存入仓库。

## 酒馆导入与送图（待开发）

用户先把某个作品文件夹保存到手机，再通过文件选择器在小说自动生成器中导入，将图片保存到酒馆内部图片库。生成时从本地读取，按当前角色取图，与提示词一起进入请求。查找时兼容完整名称和「作品 + 角色」两种写法，见 [清单约定](catalog-contract.md)。无法唯一匹配时暂停并提示，不沿用上一角色的图。

目前以改造现有小说自动生成器为主。这是路线决定，不代表代码已改造或已在手机上验证。

## 当前范围与验收

当前仓库提供按作品分文件夹的数据约定、清单工具和少量原神样本。本地导入、角色匹配、生成时送图及手机验证均未实现。

后续验收仍以实际请求为准：收集结果可追溯，作品文件夹可单独取用，导入后能为不同角色和单角色重生成送上对应图片，并且模型确实使用了这些图片。静态检查不能代替实机证据。
