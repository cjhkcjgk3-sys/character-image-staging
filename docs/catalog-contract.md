# 图片清单约定（1.1.0）

每个作品文件夹里的 `00-清单.md` 是任务名单和目录，也是机器清单的唯一来源。`catalog.json` 由 `tools/validate_catalog.py` 根据清单生成，放在同一文件夹，供以后的酒馆导入功能使用。它记录实际文件，不存放图片内容或凭据。

## 清单写法

```markdown
- [x] [温迪](温迪.jpg)
- [x] [角色甲（演出服）](角色甲（演出服）.webp)
- [ ] [芙卡洛斯](芙卡洛斯.webp)（需要更大的图片）
- [ ] 待收集角色
- [ ] 某角色（失败：未找到合适图片）
```

- 勾选表示已收集，对应机器记录的 `ready`；未勾选为 `pending`；行尾备注以「失败」开头则为 `failed`。
- 链接文本是角色名，可选 `（版本）`。作品名来自文件夹，不必写在每一行里。
- 行尾全角括号是备注。图片路径相对于本作品文件夹，不得使用绝对路径或 `..`。

生成的 `roster_name` 为 `角色名（作品）`，例如 `温迪（原神）`。酒馆侧以后查找时，先匹配完整名称，再按作品和角色兼容 `原神·温迪`、`温迪（原神）`、`原神 / 温迪` 等写法；有歧义时请用户选择，不静默选错图。这两种查找尚未实现。

## 机器清单格式

根对象含 `schema_version`（当前为 `1.1.0`）、`work` 和 `items`。一项表示一个角色的一个图片版本：

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定的 ASCII 条目 ID，同一条目更新时保持不变 |
| `roster_name` | `角色名（作品）` |
| `work` / `character` | 作品和角色名称 |
| `variant` | 外观版本，缺省为 `默认立绘` |
| `status` | `ready`、`pending` 或 `failed` |
| `image_path` | 相对于本作品文件夹的路径；尚无文件时为 `null` |
| `sha256` / `mime_type` / `size_bytes` | 实际文件的哈希、类型和字节数；无文件时为 `null` |
| `source_page` / `source_image` | 来源页面与原图片地址；未知时为 `null` |
| `note` | 清单行尾备注，可为空字符串 |

`ready` 表示已勾选，且文件存在、格式与扩展名相符、大小在 500,000 至 2,000,000 字节之间。未勾选或不合格的条目，酒馆端不得当作可用图片。同一角色和版本不能重复。重新生成时，已有条目的 `id`、`source_page` 和 `source_image` 会按角色和版本保留。

## 校验

```sh
python3 tools/validate_catalog.py images/原神
python3 tools/validate_catalog.py --check --all
```

脚本检查清单格式、勾选条目的路径、文件头、大小和哈希，并更新或核对 `catalog.json`。路径相对于作品文件夹，因此也可以检查单独解压出来的作品目录。它不判断人物是否为名单中的角色，也不证明模型已经看过图片。
