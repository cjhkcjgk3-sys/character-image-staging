# 图片清单约定（1.0.0）

`catalog/catalog.json` 是中转站和未来酒馆导入扩展之间的交接文件。它记录实际文件，不存放图片 Base64、模型生成的图片描述或账户凭据。

## 格式

根对象含 `schema_version` 和 `items`。一个条目表示一个角色的一个图片版本，完整示例见 `examples/catalog.json`。示例仅展示结构，不指向真实图片。

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定的 ASCII 条目 ID，同一条目更新时保持不变 |
| `roster_name` | 小说自动生成器名单中的完整一行，精确保留作品及角色名称 |
| `work` / `character` | 作品和角色名称，方便检索和人工核对 |
| `variant` | 外观版本，如 `默认立绘` |
| `status` | `ready`、`needs_review` 或 `failed` |
| `selection` | `automatic`、`manual` 或 `unconfirmed`；不把自动筛选冒充人工确认 |
| `image_path` | `ready` 时为仓库内 `images/` 下的相对路径；其他状态可为 `null` |
| `sha256` | `ready` 时为实际文件的 SHA-256；其他状态可为 `null` |
| `mime_type` | `ready` 时为 `image/png`、`image/jpeg` 或 `image/webp` |
| `source_page` / `source_image` | 来源页面与原图片地址；未知时填 `null` |
| `note` | 待确认或失败原因；可为空 |

`ready` 表示已选定且实际图片文件可读取，不表示人工逐张确认，也不代表模型已经看过。`needs_review` 表示身份、版本或其他关键信息不明确；`failed` 表示本轮获取失败。对这两种状态，酒馆端不得当作可用图片。

同一 `roster_name` 可以有多个 `variant`，但同一名单名和版本的组合不能重复。第一版写卡默认使用版本名为 `默认立绘` 的 `ready` 条目；若没有或不唯一，就提示处理。后续如需为每个任务指定其他版本，应明确记录选择，不按搜索排名临时猜测。

## 目录和文件

- 图片路径相对于仓库根目录，如 `images/作品甲/角色甲-默认.png`；不得使用绝对路径或 `..` 越出目录。
- 允许中文文件名；上传、URL 编码和手机文件系统差异由后续导入器处理。
- SHA-256 以文件字节计算，不因修改文件名变化。实际图片格式应与 `mime_type` 一致。
- 不同作品的同名角色以完整 `roster_name` 和 `work` 区分。缺少作品信息时先消歧，不静默合并。
- 每次更新图片后同步更新哈希和来源；清单引用的文件应在相同仓库提交中存在。

## 校验边界

`tools/validate_catalog.py` 检查基本字段、重复项、路径、文件头和可选 SHA-256。它不联网，不证明图片身份、版本、版权状态或模型识图结果；这些需要来源核对和运行时验证。
