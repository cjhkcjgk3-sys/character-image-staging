# 小说自动生成器：本地角色图片蓝图

**状态：审阅稿，等待用户确认。**本文规划在现有小说自动生成器中增加可选图片能力；当前没有改造生成器，也没有在手机上安装或验证新功能。

## 1. 要实现的体验

Agent 将角色图片整理到 GitHub 中转站，用户在网络方便时把图片 ZIP 保存到手机。之后在小说自动生成器里一次选择 ZIP，图片导入插件管理的本地图片库；批量写卡时，生成器有图就连同当前提示词一起发送给同一个模型，无图就照常按名字生成。换角色时，清理上一轮的临时图片，图片库原图保留。

```text
Agent 收图 → GitHub 图片中转站 → 下载作品包到手机
                                      ↓
                   小说生成器：一次导入 ZIP → 本地图片库
                                      ↓
名单逐人生成 → 有对应图：本轮发送名字和图片 → 当前模型直接看图
             → 没有图：本轮照常按名字生成     ＋现有文字联网搜索
             换角色清理临时图，图片库原图保留
```

一部作品可以有一百多位角色；第一版不把功能限定在原神，也不按角色逐张要求手动上传。用户的角色名单、提示词、模型和联网方式继续沿用。

## 2. 已确定、建议与待验证

- **已确定**：以现有小说自动生成器为主；GitHub 只做图片中转；需要图片时从手机一次选择 ZIP 导入本地图片库，生成时不逐张从 GitHub 下载。带图的角色将图片本身作为多模态输入，换角色清理临时图，图片库原图保留。
- **已确定**：图片文件以中文角色名命名；按作品组织；优先人物清楚，约 1 MB 为目标，2 MB 左右清楚的图片也可以使用；名字支持完整名称和作品＋角色两种查找。
- **已确定**：支持全部有图、全部纯名字，以及有图和纯名字混合；是否准备图片由用户决定。缺图、图片有歧义或附图失败时，任务按名字继续，不暂停、不跳过角色，也不因图片问题标记角色生成失败。
- **已确定**：角色名单每行右侧显示很小的本地图片缩略图；点击可看大图，右上角 X 关闭。无图的角色留空，方便用户自行补充。
- **建议，供本次审阅**：增加一个默认关闭的“自动附上角色图片”开关和“导入本地 ZIP”入口；启用后自动处理正常批量、换人和重生成。自动添加的角色图片不长期保存在聊天记录中，已有无图功能保持原样。
- **待验证**：手机实际安装的生成器版本、SillyDroid 的文件选择器与保存接口、模型当前图片内联配置、图片和联网搜索同时工作，以及真正发出的请求内容。
- **暂不做**：新建独立酒馆插件、在线逐张搜图或每轮访问 GitHub、改写模型 API/搜索代理、批量生成图片文字描述、修改酒馆视觉白名单。

## 3. 用户怎么操作

在小说生成器现有“生成设置”中增加一小块：

```text
角色参考图片
[ ] 自动附上角色图片
[导入本地 ZIP]   已导入：若干
[查看本次匹配]   带图：若干  纯名字：若干
```

1. 用户想用图时，在手机一次选中一个 ZIP，包里可以有一个或多个作品文件夹；只想用名字时无需导入。首版不增加单独选择文件夹或多选图片的入口。
2. 插件读取图片和可用的角色记录，显示导入结果；有唯一对应关系的自动匹配，待复核、有歧义或失败项可以集中查看，不要求逐张确认才能开始。
3. 用户在原有名单框输入角色。开启“自动附上角色图片”后，有图的角色自动带图；找不到、无法确定或读不了图片时，按名字继续并显示原因。面板可预览本轮匹配情况，用户也可让某个角色本次只用名字，不需要修改名单格式。
4. 按顺序生成时，每行角色右侧以微小缩略图显示已关联的图片；点图看大图、点右上角 X 关闭。没有图时不显示缩略图。补图由用户自行决定，图片问题不打断任务；换角色时清理上一轮临时图，图片库原图保留。

图片功能关闭时，不改变原有的纯文字批量写卡、续写、暂停、恢复、结果隔离及导出。

例如，假设本地只有温迪和纳西妲的图，名单依次为 `温迪（原神）`、`钟离（原神）`、`纳西妲（原神）`：插件自动按“温迪带图 → 钟离纯名字 → 纳西妲带图”生成，钟离不会使用温迪的图。关闭图片开关后，这三人都按纯名字生成；也可只把温迪临时改为纯名字。

这里的“纯名字”指插件不给该角色自动附加图库图片；聊天中本来就有的用户附件仍按酒馆现有设置处理，不会被插件删除。

### 3.1 名单缩略图与大图预览

保留原有的多行名单输入框，继续支持一次粘贴许多名字。在它下方现有的逐行角色状态名单上，给有本地图片的角色在右侧加一张很小的**真实图片缩略图**，无需另开一份名单。例如：

```text
角色状态名单                  （[图] 仅代表实际缩略图的位置）
温迪（原神）                  [图]
钟离（原神）
纳西妲（原神）                [图]
```

缩略图视觉大小接近一个字符，每个角色仍占一行；手机上给它留足够的点击区域。角色名很长时在单行内省略显示，点击名字可查看完整名称。无图留空；仍在加载或匹配不清时用轻量状态提示，避免把加载中误看成没有图。用户在同一位置点击缩略图，打开适应手机屏幕的大图，右上角 X 只关闭预览，不删除图片。生成过程中也能查看。

缩略图表示图片已经关联到该角色的本地图库，并不代表当前模型请求一定收到图片；实际送图状态另外记录。显示和放大均读取本地图片，无须访问 GitHub。为照顾上百名角色的手机性能，缩略图按可见区域异步加载，必要时只缓存很小的缩略图，不再为每行复制一份 1～2 MB 的原图。缩略图加载失败不影响任务，也不移除原图。

## 4. 本地导入与保存

### 4.1 标准作品包

优先支持已有测试包的结构：

```text
原神.zip
├── catalog/catalog.json           该作品的机器记录
└── images/原神/
    ├── 00-清单.md                  给人和 Agent 查看
    ├── 温迪.jpg
    └── 芙宁娜.webp
```

机器记录提供原名单、作品、角色、版本、图片路径、来源、状态和哈希；导入器按包内相对路径查找文件并验证实际格式，首版支持 JPEG、PNG 和 WebP。人看的任务清单和图片放在同一作品文件夹；用户不必手工编辑机器记录。

只把符合条件的图片作为图片导入；`00-清单.md` 等文本不当作图片。拒绝绝对路径或 `..` 越界路径，不能用压缩包内的路径直接覆盖酒馆其他文件。

标准包中的 `ready` 条目通过文件校验后可使用。`needs_review` 且有真实图片的条目也可导入；若名称能唯一对应，可作为待复核参考图自动发送并显示状态，不要求先逐张确认，也不把仓库状态自动改为 `ready`。名称对应只是匹配，不代表身份、版本或质量已核实。无文件、文件损坏或候选无法区分时，按名字继续，用户可以稍后选择或补图。

当前原神测试包有 8 张图片，机器记录全部为 `needs_review`；其中芙卡洛斯是剧情截图候选。**打勾表示有文件，不等于已通过质量和版本复核。**即使按名称成功匹配并选择使用，也必须保留这些状态与说明，不能把候选冒充已确认的默认立绘。

### 4.2 没有机器清单的普通 ZIP

有些 ZIP 只包含 `原神/温迪.jpg` 这样的作品文件夹和图片，没有机器清单。仍然只需选一次 ZIP：插件根据包内可用的文件夹名、中文图片文件名和任务清单建立本地对应；无法获知作品时允许用户补充，或者在角色名能够唯一匹配时使用，不要求用户回头联网或手工编辑机器清单。

普通 ZIP 中的图片按本地提供的参考图处理，不虚构官方来源或原作版本。能够唯一对应的角色自动建立映射，待复核信息如实显示；多个同名或版本无法区分时默认按名字继续。用户可以在已导入的候选中选择并记住对应关系，不强制重新命名或逐张选择。

### 4.3 存储和重复导入

- 插件界面提供自己的“本地图片库”；物理文件使用酒馆自身的图片保存接口，存进该酒馆用户的图片目录中由插件管理的范围，而不是写进插件代码安装目录或 GitHub。插件设置只保存名称、版本、本地路径、哈希和用户选择等小型索引，不保存整张图片或 Base64。此安排旨在让普通插件更新不覆盖图片，实际升级与设备迁移仍需验证。
- 按作品区分图片；中文角色名保持可读。相同内容重复导入时复用已有文件；同名但内容不同或无法安全判断时先保留已有文件并提示，不覆盖用户已有图片或聊天附件。
- 切换角色、生成结束、停止或失败时，均不删除图片库原图；同一张图可在以后重新生成角色时再次使用。
- 手机下载的 ZIP 和导入后的图片库是两份独立存储。导入功能在手机验收通过、图片核对无误后，可自行删除手机下载的 ZIP 释放空间；以后新增图片可再导入一个 ZIP。清除酒馆应用数据或迁移手机前，应先备份图片库或保留可重新导入的图片包。
- 单张保存成功并核对后才更新该张的索引。导入中断时保留已完成项，重新选择同一个包后跳过已完成项；浏览器刷新后可能需要用户重新选包。
- 计划支持任务运行中再导入 ZIP：导入在图片库独立进行，不暂停原任务；每张图片成功保存后更新名单缩略图，并可供尚未发送请求的角色使用。请求一旦发送就保持当时的图片选择，已生成的角色不会因补图自动重做，需要时使用现有“重生成此角色”。运行中导入需要手机实测。
- 导入时显示成功、待确认、失败数量。逐张处理和及时释放临时图片数据；ZIP 解析本身可能占用整包内存，约百名角色的大包需在手机上验证。如果现有解析库内存不足，优先评估插件本地提供的低内存或流式解析方式；首版的正常流程仍以一次选择一个 ZIP 为目标，设备无法处理时应明确提示，不能默称导入成功。

## 5. 两种名字查找

保留名单原文和图片原中文名，插件依次尝试：

1. **完整名称**：查找与当前名单名称对应的记录，兼容首尾空格、全角半角等常见差异。
2. **作品＋角色**：从现有记录中的作品与角色识别对应关系，兼容先后顺序和常见分隔符。

| 名单中的写法 | 图片记录 | 预期 |
| --- | --- | --- |
| `温迪（原神）` | 原神／温迪 | 匹配 |
| `原神·温迪` | 原神／温迪 | 匹配 |
| `原神 / 温迪` | 原神／温迪 | 匹配 |
| `温迪` | 图片库中唯一名为温迪的角色 | 唯一对应时匹配；存在同名歧义时按名字继续 |
| 其他作品的同名角色 | 不同作品的图片 | 能识别作品时按作品区分 |
| 用户提供的别名 | 一个或多个候选 | 能唯一对应时使用；有歧义时按名字继续，也可选择并记住 |

不因一个名字是另一个名字的部分文字就直接认定同一角色；不从整段提示词里随意猜当前角色。未指定外观时优先唯一的默认形象；多种版本无法区分时按名字继续，用户也可选择。两种主要查找方式及仅角色名的唯一匹配是待开发功能，不要求用户为了兼容而重复放图或修改原名单。

## 6. 每一轮怎样送图

1. 从生成器当前任务取得完整角色名。普通批量、指定角色重生成和候选预览重生成都显式传入该轮角色名，不能只依赖名单当前位置。
2. 在本地索引中匹配角色及形象，匹配到就尝试读取图片，并将角色、聊天、当前尝试和图片绑定为本轮临时状态。没有可用图片、用户选择不用图或读取失败时，只清理本轮自动图片并按名字继续，在状态中说明。
3. 若本轮有可用图片，复用生成器现有的生成入口和拦截链，在酒馆组装请求前向**本次请求的消息副本**加入该图片；没有可用图片就按原流程使用名字生成。角色文本替换仍按现有生成器流程进行，图片模块不额外改写聊天正文，也不永久替换原消息的附件。
4. 原有用户附件按原有方式保留；如果原消息是图库模式，仍保留原来选中的媒体，有本轮角色图时再加入。插件只负责本轮自动添加的图片；用户原来已有图片时，模型也可能一并收到它们。
5. 有图时可以使用读取后在内存中生成的图片数据 URL，避免酒馆二次取图失败时只记录日志并跳过图片；图片数据不写入聊天、插件设置或日志。酒馆以图片附件处理该数据，并与当前提示词一起交给所选模型；联网开关和搜索工具继续由用户当前配置决定。成功、失败、停止、换角色或切换聊天后清理本轮临时状态，下一轮重新匹配。

匹配预览只表示“准备带图”；只有能从实际发送流程确认时才标为已附图，无法确认时应显示未知，不能因图片库里有文件就宣称模型收到了图片。

优先让插件自动添加的图片只存在于本次请求副本中：发送完清理临时数据，聊天记录无需长期保存这张自动图片，也不会因切换角色删除图库原图。如果目标宿主只能通过聊天临时附件实现，必须先验证能够只移除插件这次添加的引用，不删除底层图库文件或用户原有附件；不能安全实现时关闭该轮自动送图，按名字继续。

酒馆通常将图片文件保存在用户图片目录，聊天附件记录的是图片路径，因此聊天显示图片并不一定意味着又存了一份同样大小的文件。本方案仍按用户要求避免长期保存自动图片的聊天引用，以免多余记录或角色图片混用。

现有 1.19.0 源码在生成前构造的 `coreChat` 是**浅拷贝**：实现时必须复制要改的 `extra` 和 `media`，不能直接修改共享数组。生成器已有 `NovelGen_isolateRoleResult` 拦截器，图片功能需与它组合，不能覆盖原有结果隔离；隔离开启或关闭都应能送图。

酒馆会捕获拦截器异常并可能继续生成；因此每轮都从干净的消息副本建立临时附图，上一轮的图不能带入下一轮。匹配或附图在发送前失败时，放弃本轮自动附图、记录“纯名字”和原因，沿用原生成流程继续，不暂停、不跳过角色、不额外触发角色重试。模型请求本身的错误和用户主动暂停／停止仍沿用生成器原有处理。实际消息副本、图库处理和错误回传均须在目标宿主实测。

启用图片功能时，应优先使用当前酒馆实际提供的能力判断，核对媒体内联和当前模型是否可用；不再维护一份新的模型名称白名单。明确不能送图时显示原因并按名字继续；无法确认时允许尝试，但标明状态未知，不宣称模型已经收到图片。能力判断通过也需要实测请求，不能仅凭开关认定模型收到了图片。

## 7. 版本与质量边界

- 目标环境是用户报告的 SillyDroid／SillyTavern 1.19.0 和 Vertex；模型白名单问题据用户反馈已处理。实际手机所装生成器版本及后续补丁尚未读取。
- 酒馆图片上传接口和本地 ZIP 库在公开 1.19.0 源码中存在；ZIP 库是否在手机安装包中可用要探测。优先使用可验证的酒馆本地库；如需备用库，应随插件本地提供，不能在导入时依赖 CDN。
- 原版 1.19.0 的 Vertex 图片路径对估算超过约 2 MiB 的图片会重新编码为 JPEG；长边超过 2048 像素时会缩小，透明背景变白。不得因此设 1 MB 硬上限；实际发给模型的画质要测试。
- 本地读图不需要访问 GitHub，但图片仍会随每次模型请求经过网络；Base64 会增加约三分之一的数据体积，模型联网搜索也仍需要网络。

| 位置 | 职责 |
| --- | --- |
| 小说生成器的角色批量运行器 | 向普通生成、重生成和预览重生成传递实际角色名 |

| 现有生成设置界面和样式 | 开关、ZIP 导入、角色状态行的小缩略图、点击大图和右上角 X、带图／纯名字状态 |
| 现有测试及必要的新增测试 | 覆盖本地导入、名称兼容、切图、重生成、失败与旧功能回归 |

具体文件以实施前核对的最新源码为准。现有版本的名单编辑为 `#nag-set-prompt` 多行输入框，下面已有 `#nag-role-results` 逐行状态列表；图片入口、缩略图和预览可复用该界面，不把图片塞进名字文本。现有世界书导入受任务运行状态和 `fileOperation` 控制；图片 ZIP 导入需要独立于这套锁，避免补图时暂停任务或改变世界书原有行为。每轮在发送前绑定当时的图片，导入新图不改变已发送的请求。保留插件 ID、现有设置与 `generate_interceptor` 行为；不修改中转仓库中的图片作为实现步骤，不增加服务器插件或更换现有模型连接。

## 9. 验收：什么才算真正完成

**自动化与隔离测试**

- 使用标准 ZIP、只包含作品文件夹和图片的 ZIP、一个包含多个作品的 ZIP、中文路径、重复导入、图片损坏和哈希不一致等样本；有问题的文件不能污染其他已导入数据。
- 验证两种名字格式、仅角色名、同名跨作品、不同版本、别名、缺图和待复核；普通缺图及歧义按名字继续，不允许静默选择错误角色或沿用上一张图。
- 覆盖全带图、全纯名字、带图 A → 无图 B → 带图 C 的混合名单、手动关闭单角色图片、重生成 A、候选预览、图片功能关闭、媒体内联不可用、图库及原附件保留、失败／停止／切聊天／刷新恢复；状态应与每次实际请求一致，原有生成、结果隔离和导出测试继续通过。
- 验证缺图、读图失败、缩略图失败、附图失败均不因图片问题暂停任务、跳过角色、标记生成失败或触发额外重试；任务已有的模型错误处理和手动控制保持原样。
- 验证名单实时匹配、缩略图在对应角色同一行右侧、无图留空、点击显示正确大图、右上角 X 只关闭预览；导入补图以及名单增删、重排、滚动后缩略图仍对应正确角色，聊天和图片库原图保持不变。
- 任务进行时导入 ZIP：任务不中断；已提交图片可供之后尚未发送的角色使用；当前已发送的请求不改变；导入失败不破坏原图库或任务。验证并发状态和旧世界书导入行为。
- 检查生成、换人、失败和停止后，聊天中没有长期保存插件自动添加的图片；用户原有附件和图片库原图完整保留，重生成仍能再次取用对应原图。
- 在隔离酒馆中阻断 GitHub 访问，导入本地包后用合成模型接口检查每轮请求的图片内容与角色对应；检查的是实际图片数据，而不仅是文件名或模型自述。

**手机实测**

1. 在 SillyDroid 用手机文件选择器一次选择本地 ZIP 并导入，确认图片存入插件管理的图片库且进度正确。
2. 用两张内容明显不同的测试图完成带图 A → 无图 B → 带图 C → 重新生成 A，确认带图角色匹配正确、无图角色没有带入上一张图；条件允许时检查请求中的图片部件，不记录凭证或图片正文。
3. 测试全部纯名字、全部带图、单角色临时不用图、缺图提示和停止恢复；网络可访问模型但无法访问 GitHub 时，本地图片仍应可用于生成。
4. 在手机上验证缩略图大小与单行显示、点击放大和右上角关闭；生成进行中导入补图，确认任务继续以及后续角色图片更新。
5. 再验证一份约百名角色的单个作品 ZIP 在手机上的导入、缩略图滚动体验与内存；若设备无法承受，记录原因并评估低内存解析，不把桌面结果当作手机通过。

第一版完成指上述核心链路可重复通过；支持上百个角色，不限定只能处理两张图。图片内容准确性和模型联网结果仍以实际图片、来源与模型输出核对。
