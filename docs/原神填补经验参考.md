## 二、关键问题排查与解决方案（重点经验）

### 1. 国内网络直连 GitHub 握手中断与 Clone 失败
- **问题现象**：`git clone` 出现 `RPC failed; curl 56 OpenSSL SSL_read: ... unexpected EOF while reading; fatal: early EOF`。
- **原因分析**：国内网络直连 GitHub 时，OpenSSL 在大包/大 pack 传输时容易遭遇 TCP RST 或握手阻断。
- **解决方案**：
  1. 切换 Windows 原生 Schannel TLS 通道：
     ```bash
     git config --global http.sslBackend schannel
     ```
  2. 采用免拉取 Blob 的轻量克隆（Blobless Clone）：
     ```bash
     git clone --filter=blob:none <repo-url>
     ```
     仅拉取 commit 与 tree 元数据，秒级完成克隆，极大规避网络大包中断。

---

### 2. PowerShell 管道重定向导致的二进制乱码
- **问题现象**：使用 PowerShell 将 CLI 二进制流重定向到文件（例如 `gh api ... > image.png`），图片体积异常膨胀且无法打开。
- **原因分析**：PowerShell 默认会将重定向输出按照文本编码（如 UTF-16LE 或 ANSI）重新转码，破坏原始图片的二进制字节。
- **解决方案**：
  - 严禁用文本重定向保存图片。
  - 统一编写轻量 Python 脚本，以二进制模式（`open(..., 'wb')`）直接将原始字节写入磁盘。

---

### 3. GitHub API 批量请求超限与 Unexpected EOF
- **问题现象**：
  - 使用 `-H "Accept: application/vnd.github.raw"` 请求大文件（>1MB）时，GitHub API 经常在传输中途断开连接报 `unexpected EOF`。
  - 线程数过高（>5 线程）并发调用 `gh api` 会触发 GitHub API 速率限制或连接阻断（retcode 1）。
- **解决方案**：
  1. **首选获取 tree 缓存**：单次通过 `repos/{owner}/{repo}/git/trees/main?recursive=1` 获取全仓库索引并本地持久化为 `tree_cache.json`，后续直接查询 SHA，杜绝无意义的重复 API 查询。
  2. **降低并发**：采用 2~3 个 Worker 线程或串行请求，并在请求间设置 `time.sleep(1)`，成功率从不足 30% 跃升至 100%。
  3. **数据格式选型**（不推荐，见文首）：对 1MB 以下小图，通过默认 JSON 接口拉取 Base64 字符串并在本地解码写入，传输稳定性远高于直接流式传输。

---

### 4. 极端超大立绘与国内 CDN 备选数据源
- **问题现象**：个别角色（如恰斯卡源图达 17.7MB，布伦妮 1.6MB）在网络高峰期通过 GitHub API 频繁遭遇超时或下载中断。
- **解决方案**：
  - **启用高可用国内镜像/WIKI 源**：原神官方角色立绘均在 Bilibili Game Wiki (BWIKI) 上有镜像托管。
  - 通过公开 MediaWiki API 解析角色立绘直链：
    ```
    https://wiki.biligame.com/ys/api.php?action=query&titles=File:角色名立绘.png&prop=imageinfo&iiprop=url&format=json
    ```
  - 从 `https://patchwiki.biligame.com/` 国内 CDN 下载，下载速度可达毫秒级，且无需科学上网或 GitHub Token。

---

### 5. 图片体积区间自适应归一化 (Pillow 算法)（已过时：放大凑体积已禁止，见文首）
- **问题现象**：部分源图体积过大（>2MB）或过小（<500KB，如早期角色小图仅 300KB），直接保存会被 `check.py` 判定违规拦截。
- **解决方案**：设计自适应 Pillow 处理逻辑：
  - **超大图压缩（>2MB）**：
    - 若含透明通道（RGBA/P）：优先保存为 WebP（quality=90~92）。
    - 若仍超出或为纯色 RGB：转换为 RGB 模式保存为 JPEG（quality=85~94）。
  - **过小图升频（<500KB）**：
    - 首选转为无损 PNG 重新编码；
    - 若仍然低于 500KB，使用高保真 Lanczos 插值算法等比缩放 1.25~1.3 倍后保存为 PNG 或高画质 JPEG（quality=95~96），使文件体积自然稳定在 500KB~2MB 区间。
  - **Magic Bytes 校验**：保存后比对前 12 字节（`\x89PNG` / `\xff\xd8\xff` / `RIFF....WEBP`），杜绝扩展名与格式不匹配。

---

### 6. 清单 Markdown 全角括号约定与自动化双向同步
- **问题现象**：角色带有版本或形态标注时（如 `芙卡洛斯（神装）`），手写或简易正则容易丢失全角括号，或将已收集状态误标。
- **解决方案**：
  - ~~严格保持全角括号在 Markdown 链接外部~~（错误，见文首）：形态写在链接文字里，`- [x] [芙卡洛斯（神装）](芙卡洛斯（神装）.jpg)`。
  - 使用标准自动化同步脚本比对磁盘真实文件与清单行，一键更新勾选状态，杜绝人工修改漏项。
