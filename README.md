# 角色图片中转站

这个仓库用于整理和中转不同作品的角色图片：模型或 Agent 收集图片与来源，酒馆扩展将选定图片导入酒馆内部，再在批量写卡时交给当前模型的多模态输入。

**当前状态：项目骨架和一批图片测试样本。** 仓库中已有 8 张原神角色图片候选，尚未按最新质量规则复核；自动收图、本地导入、逐角色送图和手机实测尚未完成。

## 使用流程

1. 在作品文件夹的 `00-清单.md` 中列出要收集的角色，待收集项留空框；名单可由用户提供，也可由有联网能力的 Agent 根据用户确定的范围整理。
2. 让具备联网、图片查看和仓库写入能力的模型或 Agent 处理未勾选项，以及标记为待复核的图片，并记录来源。
3. 图片与目标角色、版本对应时，存入作品文件夹并在清单打勾；身份或版本有歧义时保留空框，标注待确认。
4. 收集到的图片及来源、路径等机器记录一起提交到本仓库；批量写卡前核对「小说自动生成器」中的实际名单名称。
5. 将作品图片与机器清单打包成 ZIP 下载到手机，通过将来开发的小说生成器功能一次导入插件管理的本地图片库。
6. 批量写卡时，有对应图片就把**图片本身**作为多模态输入发送给当前模型；没有图片则照常按名字生成，同一份名单可混合。切换角色时只清理临时图片，不删除图片库原图。

图片文字描述可以作为辅助资料，但不能代替第 6 步的图片输入。普通搜索桥方案保留为备选。

## 目录

```text
catalog/catalog.json       机器可读图片清单，首批为待核对的图片候选
docs/design.md             总体方案、首版范围和验收
docs/catalog-contract.md   清单格式和读写约定
docs/image-guidelines.md   图片质量、压缩、中文命名和目录规则
examples/catalog.json      虚构条目的格式示例，不是收集结果
images/                    已收集的图片；按作品组织
tasks/                     可恢复的收集任务和待确认记录
tools/validate_catalog.py  检查清单、文件路径和图片哈希
NEXT.md                    当前项目状态和下一步
```

`catalog/catalog.json` 是待导入的图片清单。图片与清单需要一起维护，不能把图片链接、缩略图或文字简介当成已经保存的原图。示例中的名称均为虚构，不参与实际导入。

收集与整理图片时，参阅[角色图片收集与整理方法](docs/image-guidelines.md)。

小说自动生成器的后续改造见[本地角色图片蓝图（审阅稿）](docs/小说生成器-本地角色图片蓝图.md)。

2026-11-12 的原神试收集包含八张测试图片和对应来源。它们都标记为 `needs_review`：需要按人物优先的新规则复核，名单名称也尚未与用户的实际名单核对。芙卡洛斯的图片是剧情截图候选，不是已确认的独立立绘。

每个作品目录放一份 `00-清单.md`，例如[原神角色图片清单](images/原神/00-清单.md)：先把要收集的名字列进去，Agent 再处理未勾选和待复核的项目。打勾表示目标形象的图片已经存入仓库；未勾表示仍待收集或确认，行尾可注明已有候选。它也可通过名字链接打开已有图片。版本、来源和复核状态保存在机器清单；图片或其机器记录变更时同步更新。目前由人或 Agent 维护，尚未自动同步。

清单名前的 `00-` 让按名称排序的界面更容易把它放在前面；图片文件仍使用中文角色名。原神目录中的旧 `清单.md` 是历史链接的跳转入口，不是第二份任务清单。

## 检查清单

在仓库根目录运行：

```sh
python3 tools/validate_catalog.py
python3 tools/validate_catalog.py --check-hashes
```

前一条检查清单格式和 `ready` 条目的文件；后一条还计算这些文件的 SHA-256。`needs_review` 候选图片的文件与哈希目前需要单独检查。示例可用 `python3 tools/validate_catalog.py examples/catalog.json` 检查。验证清单不代表已安装扩展，也不代表模型已经收到图片。

## 与酒馆的关系

酒馆侧应当保存图片的实际内容，而非只把 URL 或图片描述塞进提示词。用户希望先把作品 ZIP 下载到手机，一次选入酒馆，后续批量写卡直接使用插件图片库中的本地副本，不受每轮 GitHub 下载波动影响。图片是可选的：有图发图，无图按名字继续，亦可选择全程只用名字。自动角色图不长期留在聊天记录中，换人不删除图片库原图。图片仍需随每次请求发送给模型；模型 API 和联网搜索仍需要网络。

仓库目前只提供中转数据结构；手机选文件、批量导入、酒馆内部保存及生成时切图均尚未实现，也尚未在 SillyDroid 实机验证。

公开仓库中的内容可被他人读取和下载；收集图片时记录来源，并核对其是否适合公开存放。不要将令牌、密钥或私人聊天内容写进仓库。

## 访问权限

当前仓库为公开仓库；仓库所有者以后可在 GitHub 的 **Settings → General → Danger Zone → Change visibility** 中改为私有。私有后，需要仓库访问权限才能读取图片。

让有网络和 GitHub 访问能力的 Agent 使用私有仓库时，可以授权 GitHub App 访问该仓库，或使用只覆盖本仓库的细粒度令牌：仅下载图片使用 Contents 只读权限，收集并上传图片则使用 Contents 读写权限。令牌应通过 Agent 所在平台的凭据配置或密钥环境变量提供，不要写入仓库、图片链接或聊天正文；具体接入方式取决于使用的平台。
