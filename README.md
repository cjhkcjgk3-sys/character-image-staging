# 角色图片中转站

> 协作的 AI 先读 [AGENTS.md](AGENTS.md) 和 [开发准则](docs/开发准则.md)。

按作品整理角色图片，供「小说自动生成器」批量写卡时导入酒馆使用。本仓库只做收集和中转，图片导入与送图由小说自动生成器完成（见「在小说生成器里使用」）。

> **仓库分工**：本仓库放 原神、崩坏：星穹铁道、绝区零、明日方舟、终末地、鸣潮、异环。碧蓝航线（本体与皮肤）在 [character-image-staging-azurlane](https://github.com/cjhkcjgk3-sys/character-image-staging-azurlane)；其余作品在 [character-image-staging-2](https://github.com/cjhkcjgk3-sys/character-image-staging-2)。单个仓库接近 1 GB 时再开新仓库。

## 目录

一部作品一个文件夹，清单、图片都在里面，下载一个文件夹即可：

```text
images/原神/
  00-清单.md      任务名单和目录（请保持这个文件名，打开文件夹时会排在最前）
  温迪.jpg        以中文角色名命名的图片
images/星穹铁道/  当前 61 项角色立绘均已收集
examples/作品模板/00-清单.md
```

`00-清单.md` 是唯一数据。勾选表示图片已收集；角色名是指向图片的相对链接。格式约定见下方「清单格式」。

## 清单格式

清单开头可用一行写出本作品的其他称呼，方便去掉「星铁·姬子」这类前缀；没有这一行时，校验脚本仍认识常用简称。文件夹名始终有效。

```text
作品别名：崩坏：星穹铁道、崩坏星穹铁道、星铁
```

角色行只写角色名，作品来自文件夹，不必写进名字里。链接文字和图片文件名（不含扩展名）要逐字相同。其他称呼跟在「别名：」后面。同一角色的不同版本或形态单独一行，版本写在全角括号里，作为名字的一部分：

```text
- [ ] 角色名
- [x] [姬子](姬子.jpg)
- [x] [雷电将军](雷电将军.jpg) 别名：雷电影、影
- [x] [三月七](三月七.jpg)
- [x] [三月七（巡猎）](三月七（巡猎）.jpg)
```

请使用全角括号「（）」；半角 `()` 容易破坏 Markdown 链接。名字或文件名里若有空格、半角括号，链接写成 `[名字](<文件名.jpg>)`，或把路径做 URL 编码。`别名：` 和 `别名:` 都可以，多个别名用顿号、逗号或斜杠分隔。行尾其他备注在检查图片时会忽略。未勾选项可在行尾写 `备注：…`（例如待重找的原因），它不算名字或别名。

## 收集一张图

1. 找到一张人物清楚、主体完整的角色立绘。画面上有文字或背景可以接受，只要角色本身清楚；从 Fandom / Wikia CDN 取图时可在地址后加 `format=original` 获取较高分辨率版本。优先辨认眼睛颜色、脸部细节和服装，不用背景细节换取人物清晰度。
2. 按简体中文角色名保存为 `images/<作品>/<角色名>.jpg`、`.png` 或 `.webp`，单图必须小于 1,000,000 字节，不设最低体积。大小只是仓库上限，不是清晰度指标；清晰原图低于 500 KB 时无需放大或重新编码。超限图按需裁剪后再压缩：先 `python3 tools/crop_character.py images/<作品>` 看预览，确认人物完整居中后加 `--apply`（规则见通用经验第四节）。
3. 在该作品的 `00-清单.md` 中勾选对应角色，并把名字链接到这个文件；如有需要再加上别名。
4. 批量收集完成后，可运行 `python tools/audit_framing.py images/<作品>`，按页总览清单中全部已勾选图片的构图（包括旧图）；脚本生成本地 HTML 图库，不改图片或清单。再运行 `python3 tools/defect_check.py <作品> --sheet`，自动标出缺头缺脸、被矩形裁掉、脸部透明空洞或只剩背景图层的疑似残图，只需打开被标记的图确认（需 `pip install pillow numpy opencv-python-headless`，结果写到不提交的 `out/defect_check/`）。最后提交到本仓库。不必手动运行仓库检查脚本；CI 会自动检查已勾选项：文件是否存在、是否在本文件夹内、扩展名与文件头是否相符、图片文件结构是否完整、文件是否小于 1,000,000 字节。同一作品里别名或名称冲突时会给出警告。批量收图时还要对图片做完整解码；经验和常见坑见[图片收集通用经验](docs/图片收集通用经验.md)。

## 添加新作品

在 `images/` 下新建文件夹，名称使用作品的常用中文名，例如 `images/星穹铁道/` 或 `images/崩坏3/`。复制 [examples/作品模板/00-清单.md](examples/作品模板/00-清单.md) 到新目录，保持文件名为 `00-清单.md`，再按上面四步收集图片。默认只收集本体立绘（含改造、律者等主要形态）。只有明确要求给某部作品收集皮肤时才收，而且要收就全收，不要挑着收。皮肤立绘放在清单单独的「## 皮肤」小节，命名 `角色名（皮肤名）`，规则见[图片收集通用经验](docs/图片收集通用经验.md)中的「皮肤立绘收录规则」。

## 手机下载

打开本仓库的 [图片下载](https://github.com/cjhkcjgk3-sys/character-image-staging/releases/tag/downloads) 页面，点要下的作品即可，例如原神是 `genshin.zip`。页面上有中文作品名和英文文件名的对照。图片有更新时，这个页面会自动换成最新的包。还没有图片的作品（例如目前的鸣潮、异环）不会出现在列表里。

下好后，在小说自动生成器的批量写卡里「导入作品 ZIP」，再用「📋 从清单添加到名单」勾选角色。压缩包上限 1 GB。

若只想自己打包某个文件夹，也可用 [download-directory](https://download-directory.github.io/?url=https://github.com/cjhkcjgk3-sys/character-image-staging/tree/main/images/%E5%8E%9F%E7%A5%9E) 或本地 `zip -r 原神.zip images/原神`。不必等清单全部勾选，可先打包已有图片。

## 在小说生成器里使用

小说自动生成器 1.13 起支持作品 ZIP 图片库（1.15.1 为当前版本）：

1. 打开本仓库的 [图片下载](https://github.com/cjhkcjgk3-sys/character-image-staging/releases/tag/downloads) 页面，把要导入的作品 ZIP 下到手机（清单已打在包里；压缩后上限 1 GB）。
2. 在生成器的批量写卡里“导入作品 ZIP”。导入只读目录并生成小缩略图，原图在点开或发送时才读取。
3. 点“📋 从清单添加到名单”，勾选角色后“➕ 加入名单”，名字按清单原样加入，重复的自动跳过。生成角色卡默认只用本体立绘；皮肤在单独的折叠分组里，默认不勾选，可按需要做成服装卡或作为素材资料保存。
4. 名单每行左边是名字、右边是缩略图：有缩略图＝有图，虚线空框＝无图，“?”＝多张候选无法确定。点缩略图看大图。

写卡时有图就把图片和名字一起发给模型，没有图或匹配不明确就照常按名字写卡，不暂停、不跳过角色。名字匹配规则见[图片收集通用经验](docs/图片收集通用经验.md)第五节；所以清单里的名字、备注写法要和图片文件名逐字一致。

## 模型说明

当前按酒馆的 Chat Completion 来配置，使用两个来源：

- **Google Vertex AI**：可发送图片，请开启「发送内嵌媒体 / Send inline images」，并开启「启用网页搜索」。Gemini 在启用函数调用（function calling / tools）时会跳过网页搜索，因此这条流程请关闭函数调用。
- **自定义 OpenAI 兼容接口**：酒馆默认把自定义来源当作支持识图，开启「发送内嵌媒体 / Send inline images」后会发送图片。自定义来源没有酒馆自带的网页搜索开关；能否搜索取决于中转或模型本身（尚未核实）。若中转不提供搜索，就依靠图片和模型已有知识。
