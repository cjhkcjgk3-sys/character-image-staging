# 角色图片中转站

按作品整理角色图片，供「小说自动生成器」批量写卡时导入酒馆使用。本仓库只做收集和中转；酒馆侧的导入与送图尚未开发。

## 目录

一部作品一个文件夹，清单、图片都在里面，下载一个文件夹即可：

```text
images/原神/
  00-清单.md      任务名单和目录（请保持这个文件名，打开文件夹时会排在最前）
  温迪.jpg        以中文角色名命名的图片
images/星穹铁道/  以后可按同样方式增加作品
examples/作品模板/00-清单.md
```

`00-清单.md` 是唯一数据。勾选表示图片已收集；角色名是指向图片的相对链接。格式约定见下方「清单格式」。

## 清单格式

清单开头可用一行写出本作品的其他称呼，方便去掉「星铁·姬子」这类前缀；没有这一行时，校验脚本仍认识常用简称。文件夹名始终有效。

```text
作品别名：崩坏：星穹铁道、崩坏星穹铁道、星铁
```

角色行只写角色名，作品来自文件夹，不必写进名字里。其他称呼跟在「别名：」后面。同一角色的不同版本或形态单独一行，版本写在全角括号里，作为名字的一部分：

```text
- [ ] 角色名
- [x] [姬子](姬子.jpg)
- [x] [雷电将军](雷电将军.jpg) 别名：雷电影、影
- [x] [三月七](三月七.jpg)
- [x] [三月七（巡猎）](三月七（巡猎）.jpg)
```

请使用全角括号「（）」；半角 `()` 容易破坏 Markdown 链接。名字或文件名里若有空格、半角括号，链接写成 `[名字](<文件名.jpg>)`，或把路径做 URL 编码。`别名：` 和 `别名:` 都可以，多个别名用顿号、逗号或斜杠分隔。行尾其他备注在检查图片时会忽略。

## 收集一张图

1. 找到一张能看清该角色整体外形和模样的图片。画面上有文字也可以，只要人物可辨认。从 Fandom / Wikia CDN 取原图时请在地址后加上 `format=original`，否则常会得到大约 100 KB 的压缩 webp，达不到大小要求。
2. 保存为 `images/<作品>/<角色名>.jpg`、`.png` 或 `.webp`，大小 500 KB 至 2 MB（按 500,000 至 2,000,000 字节计算）。
3. 在该作品的 `00-清单.md` 中勾选对应角色，并把名字链接到这个文件；如有需要再加上别名。
4. 提交到本仓库。不必手动运行检查脚本；CI 会自动检查已勾选项：文件是否存在、是否在本文件夹内、扩展名与文件头是否相符、大小是否在范围内。同一作品里别名或名称冲突时会给出警告。

## 添加新作品

在 `images/` 下新建文件夹，名称使用作品的常用中文名，例如 `images/星穹铁道/` 或 `images/崩坏3/`。复制 [examples/作品模板/00-清单.md](examples/作品模板/00-清单.md) 到新目录，保持文件名为 `00-清单.md`，再按上面四步收集图片。

## 下载单个作品

不必下载整个仓库。打开作品文件夹后，可用 [download-directory](https://download-directory.github.io/?url=https://github.com/cjhkcjgk3-sys/character-image-staging/tree/main/images/%E5%8E%9F%E7%A5%9E) 只打包 `images/原神/`；其他作品把链接里的路径换成对应文件夹即可。若已克隆仓库，也可以只压缩该目录：

```sh
zip -r 原神.zip images/原神
```

不必等清单全部勾选；可先打包已有图片，后续再补充。

## 以后怎么用

用户把作品文件夹打成 ZIP 下载到手机后，在小说自动生成器里一次选择 ZIP，导入插件管理的本地图片库。批量写卡时，有对应图片就把图片和名字一起发给模型；没有图片或匹配不明确时照常按名字写卡，同一份名单可以有图和无图混合，也可以全程只用名字。自动附上的角色图不长期留在聊天记录中；换人只清理临时引用，不删除图片库原图或用户原有附件，也绝不沿用上一角色的图。

图片是否齐全由用户决定，缺图或附图失败不会暂停任务或跳过角色。计划在现有角色状态名单每行右侧显示微小缩略图：有图可点开放大，右上角 X 关闭预览；计划支持任务运行中导入 ZIP 补图，后续尚未发送的角色即可使用。缩略图表示本地图库已有对应图片，实际送图情况另行记录。

匹配前先规范化名字：去掉首尾空白，统一全角与半角，去掉空格和间隔点，并只去掉作品名的前缀或后缀（文件夹名或「作品别名：」里的简称，如 `星铁`）。因此 `原神·温迪`、`温迪（原神）`、`【原神】温迪`、`崩坏星穹铁道·姬子`、`姬子（星穹铁道）` 会落到对应角色；`三月七（巡猎）` 不会当成普通的 `三月七`。先精确比较链接文本、别名和图片文件名（不含扩展名）；仍没有结果时，若某一条能唯一包含或更完整地解释查询（例如 `巡猎三月七` 对上 `三月七（巡猎）`），也可以匹配。没有结果或有多条可能时，提示原因并按名字继续写卡，不附图。`tools/check.py` 的 `normalize_name` 与 `match_name` 可供参考；酒馆侧还需要按作品区分，避免把不同作品的同名角色当成同一人。查找、导入和送图都尚未实现。更完整的改造计划见[小说生成器本地角色图片蓝图](docs/小说生成器-本地角色图片蓝图.md)。

## 模型说明

当前按酒馆的 Chat Completion 来配置，使用两个来源：

- **Google Vertex AI**：可发送图片，请开启「发送内嵌媒体 / Send inline images」，并开启「启用网页搜索」。Gemini 在启用函数调用（function calling / tools）时会跳过网页搜索，因此这条流程请关闭函数调用。
- **自定义 OpenAI 兼容接口**：酒馆默认把自定义来源当作支持识图，开启「发送内嵌媒体 / Send inline images」后会发送图片。自定义来源没有酒馆自带的网页搜索开关；能否搜索取决于中转或模型本身（尚未核实）。若中转不提供搜索，就依靠图片和模型已有知识。

当前原神样本中，温迪、钟离、雷电将军、纳西妲、芙宁娜、芙卡洛斯、玛薇卡、安娜丝塔夏均已勾选。酒馆端蓝图不将该大小范围设为硬门槛，仓库现有检查规则本轮未改。
