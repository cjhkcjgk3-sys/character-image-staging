# 角色图片中转站

这个仓库用于整理和中转不同作品的角色图片：模型或 Agent 收集图片与来源，酒馆扩展将选定图片导入酒馆内部，再在批量写卡时交给当前模型的多模态输入。

**当前状态：项目骨架。** 尚未实现自动收图、酒馆扩展、仓库同步或手机实测；当前没有角色图片。

## 使用流程

1. 在「小说自动生成器」中准备角色名单，名单中的每一行包含作品和角色的完整名称。
2. 将名单交给具备联网、图片查看和仓库写入能力的模型或 Agent；它寻找合适的立绘并记录来源。
3. 图片归属和版本明确时自动处理；多个角色、版本或来源无法区分时标记为待确认，由用户选择。
4. 收集结果以图片文件和 `catalog/catalog.json` 中的记录一起提交到本仓库。
5. 将来由独立的酒馆扩展读取清单，下载选定图片并保存到酒馆内部图片库。
6. 批量写卡时，扩展根据本轮完整角色名取对应图片，把**图片本身**作为多模态输入发送给当前模型。

图片文字描述可以作为辅助资料，但不能代替第 6 步的图片输入。普通搜索桥方案保留为备选。

## 目录

```text
catalog/catalog.json       机器可读图片清单，初始为空
docs/design.md             总体方案、首版范围和验收
docs/catalog-contract.md   清单格式和读写约定
examples/catalog.json      虚构条目的格式示例，不是收集结果
images/                    已收集的图片；按作品组织
tasks/                     可恢复的收集任务和待确认记录
tools/validate_catalog.py  检查清单、文件路径和图片哈希
NEXT.md                    当前项目状态和下一步
```

`catalog/catalog.json` 是待导入的图片清单。图片与清单需要一起维护，不能把图片链接、缩略图或文字简介当成已经保存的原图。示例中的名称均为虚构，不参与实际导入。

## 检查清单

在仓库根目录运行：

```sh
python3 tools/validate_catalog.py
python3 tools/validate_catalog.py --check-hashes
```

前一条检查清单格式和已登记文件；后一条还逐个计算文件的 SHA-256。示例可用 `python3 tools/validate_catalog.py examples/catalog.json` 检查。验证清单不代表已安装扩展，也不代表模型已经收到图片。

## 与酒馆的关系

酒馆扩展应当保存图片的实际内容，而非只把 URL 或图片描述塞进提示词。仓库目前只提供中转数据结构；酒馆内部的保存位置、批量导入、生成拦截以及 SillyDroid 的权限和网络访问还需要针对真实环境实现与验证。

公开仓库中的内容可被他人读取和下载；收集图片时记录来源，并核对其是否适合公开存放。不要将令牌、密钥或私人聊天内容写进仓库。
